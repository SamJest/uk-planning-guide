# 24-Month Roadmap to Category Leadership

The traffic figures below are operating thresholds, not guarantees. Progression depends on current baseline, crawl/index recovery, authority, links, content quality and product adoption.

## Phase 0 — Weeks 1–3: stop quality leakage

### Outcomes

- generator and content flow documented;
- typed page-family schemas;
- source registry;
- contamination scanner;
- 20-page canary;
- placeholder UI removed;
- reviewer/date/source inconsistencies fixed;
- URL/canonical/sitemap/link tests;
- affected URL inventory and repair/noindex/redirect plan.

### Exit gates

- zero known cross-family contamination in canary;
- 100% source-family match;
- zero broken canary internal links;
- no placeholder/demo content;
- visible date = structured-data date = sitemap date when applicable;
- all canary pages pass accessibility and schema tests.

### Traffic objective

Protect and recover existing visibility. Do not chase page-count growth.

## Phase 1 — Weeks 4–8: rebuild the platform foundation

### Outcomes

- shared CSS/JS assets;
- reusable page components;
- URL registry;
- fast internal search;
- simplified navigation;
- page-type schemas;
- analytics event dictionary;
- performance budgets;
- top 100 landing pages repaired.

### Exit gates

- normal content pages meet size/performance budgets;
- top 100 pages have clear intent and source panels;
- no crawlable thin search/filter states;
- mobile task completion tested.

## Phase 2 — Months 3–4: My Planning Project 2.0

### Outcomes

- multiple project support;
- tasks and due dates;
- document/evidence checklist;
- rule-engine versioning;
- project timeline;
- local-first storage migration;
- optional passwordless account;
- cross-device sync;
- project export;
- notification preferences.

### Exit gates

- anonymous use remains fully functional;
- account conversion occurs only after value;
- users can export/delete data;
- 7-day return cohort is measured;
- no sensitive notes in analytics.

### Product target

At least 10% of completed route checks create or update a project after iterative optimization.

## Phase 3 — Months 4–6: authority data and alert pilot

### Outcomes

- 20–50 deeply sourced authority profiles;
- source-change jobs;
- council-watch weekly digest;
- application-watch pilot;
- “what changed” feed;
- first nearby-decision prototype;
- public methodology.

### Exit gates

- supported authorities show source coverage clearly;
- unsupported authorities degrade gracefully;
- alert accuracy and latency measured;
- no brittle nationwide rollout;
- user can unsubscribe/delete watches.

### Stretch traffic threshold

50,000–100,000 monthly visits only if quality recovery, indexing and content demand support it.

## Phase 4 — Months 5–9: national authority build

### Outcomes

- 50–70 cornerstone guides;
- 150–250 validated local/project pages;
- original diagrams;
- 20 case studies;
- updates hub;
- first original planning-data report;
- journalist/press resource page;
- embeddable utility.

### Exit gates

- all indexed local pages meet 85/100 quality threshold;
- updates link back to affected evergreen pages;
- first external links/citations to original assets;
- content refresh workflow operating.

### Stretch traffic threshold

100,000–175,000 monthly visits.

## Phase 5 — Months 8–12: scale only proven clusters

### Outcomes

- 100+ cornerstone pages;
- broad authority profiles;
- 500–900 high-quality local/project pages;
- application/council alerts expanded to reliable authorities;
- 50+ case studies;
- monthly data stories;
- strong email/project return loop.

### Exit gates

- local page cohorts outperform national-only equivalents;
- alert users have materially higher 30/90-day retention;
- no index-quality regression;
- authority/source freshness SLA is met.

### Stretch traffic threshold

150,000–250,000 monthly visits.

## Phase 6 — Months 12–18: proprietary planning intelligence

### Outcomes

- normalized decision-time and requirement datasets;
- council comparison dashboards;
- refusal-reason taxonomy;
- expanded application monitoring;
- annual State of Homeowner Planning report;
- public methodology and selected downloads;
- expert contributor/case-study network;
- transparent referral marketplace.

### Exit gates

- data coverage and limitations are published;
- data pages earn links and returning users;
- referral monetization does not reduce route-tool completion;
- update operations are sustainable.

### Stretch traffic threshold

250,000–375,000 monthly visits.

## Phase 7 — Months 18–24: category-leader push

### Outcomes

- national + local + recurring product coverage;
- mature application/policy tracking;
- high-quality authority coverage;
- regular original data/publications;
- strong brand search;
- press citations;
- direct/email/PWA return traffic;
- selective partnerships and embeds.

### Operating target

400,000–500,000+ monthly visits.

## Team/capability requirements

Even with Codex handling substantial implementation, category leadership requires human functions:

- editorial/source verification;
- planning-domain review;
- data operations;
- product analytics;
- outreach/digital PR;
- user support and privacy;
- commercial partner quality control.

Do not imply code alone can produce authority, links or reliable legal-context content.

## Quarterly decision gates

At each quarter ask:

1. Which page clusters generate qualified visits and project actions?
2. Which local pages have genuine unique value?
3. Which alerts drive return visits?
4. Which tools overlap and should be consolidated?
5. Which sources are costly or unreliable?
6. Which content is decaying?
7. Which original assets earned links?
8. Has trust improved?
9. Is monetization helping or interrupting the user?
10. Is the 500,000-visit model still supported by actual cohort data?
